# 🛍️ متجري - متجر إلكتروني متكامل

موقع متجر إلكتروني كامل (Frontend + Backend حقيقي) جاهز للتشغيل والتخصيص، مبني بـ:
- **Backend**: Node.js + Express + قاعدة بيانات SQLite (لا تحتاج تنصيب أي سيرفر قاعدة بيانات منفصل)
- **Frontend**: HTML + Tailwind CSS + JavaScript خالص بهوية بصرية مميزة (لا يحتاج خطوة بناء/Build)
- **عنوان دقيق بكل الوطن**: اختيار الولاية ثم البلدية من قوائم منسدلة تغطي كل الولايات الـ69 و1541 بلدية (حسب آخر تقسيم إداري رسمي 2026)
- **سعر توصيل مرن**: سعران مختلفان لكل ولاية (توصيل للمنزل / توصيل لمكتب البريد)، تضبطهما أنت من لوحة التحكم
- **معرض صور تفاعلي**: كل منتج يمكن أن يحتوي حتى 6 صور، يتصفحها الزبون بالتمرير (Swipe) على الجوال أو الأسهم على الحاسوب، مع إمكانية تكبير أي صورة (Lightbox) بالضغط عليها
- **الأمان**: Helmet, Rate Limiting, تشفير كلمات المرور bcrypt, جلسات JWT بكوكيز محمية HttpOnly, تحقق صارم من كل المدخلات، وإعادة حساب كل الأسعار (المنتجات + التوصيل) والمخزون من السيرفر عند كل طلب لمنع أي تلاعب من المتصفح أو بيع مضاعف لآخر قطعة متوفرة

## 1) التشغيل خطوة بخطوة

### المتطلبات
- Node.js نسخة 18 أو أحدث ([حمّله من هنا](https://nodejs.org))

### الخطوات

```bash
# 1. ادخل لمجلد المشروع
cd ecommerce-store

# 2. ثبّت الحزم
npm install

# 3. انسخ ملف الإعدادات وعدّله
cp .env.example .env
```

افتح ملف `.env` وعدّل **إلزاميًا**:
- `JWT_SECRET`: ضع نصًا عشوائيًا طويلًا وسريًا جدًا (يمكنك توليده بالأمر: `openssl rand -hex 32`)
- `ADMIN_USERNAME` و `ADMIN_PASSWORD`: بيانات دخولك للوحة التحكم (اختر كلمة مرور قوية)
- `STORE_NAME` و `STORE_URL`: اسم متجرك ورابطه بعد النشر

```bash
# 4. أنشئ حساب الأدمن (مرة واحدة فقط)
npm run seed:admin

# 5. شغّل الموقع
npm start
```

الموقع سيعمل على: `http://localhost:3000`
لوحة التحكم: `http://localhost:3000/admin.html`

## 2) استخدام لوحة التحكم

### إضافة التصنيفات (زر +)
من تبويب **"التصنيفات"**:
- اضغط **"+ إضافة تصنيف رئيسي"** لإنشاء تصنيف جديد من الصفر (مثال: ملابس، إلكترونيات).
- بجانب أي تصنيف موجود يوجد زر **"+"** دائري، اضغطه لإضافة تصنيف فرعي بداخله (مثال: داخل "ملابس" أضف "رجالي"، وداخل "رجالي" أضف "قمصان"...).
- لا يوجد حد لعدد المستويات، تقدر تبني شجرة تصنيفات بالعمق الذي تريده.
- زر "حذف" يحذف التصنيف وكل ما بداخله من تصنيفات فرعية تلقائيًا.

### إضافة المنتجات
من تبويب **"المنتجات"** اضغط **"+ منتج جديد"**: أدخل الاسم، السعر، الوصف، اختر التصنيف، وارفع حتى 6 صور.

للمخزون خياران عند الإنشاء:
- **منتج بسيط**: أدخل الكمية الابتدائية وسعر الشراء للقطعة.
- **منتج بمقاسات/أحجام**: فعّل خيار "لهذا المنتج مقاسات/أحجام مختلفة" وأضف أي عدد من المقاسات بأسماء حرة تمامًا (مثلًا 38 إلى 44 للأحذية، أو S إلى XXL للملابس، أو أي تسمية أخرى)، لكل مقاس كميته وسعر شرائه المستقلان تمامًا. ضع 0 لأي مقاس غير متوفر حاليًا فيظهر للزبون كـ"نفد" دون حذفه.

**مهم**: المخزون لا يُعدَّل أبدًا بالكتابة فوق رقم مباشرة من نافذة التعديل (لمنع كتابة رقم قديم فوق رقم تغيّر فعليًا في الخلفية بسبب طلب جديد). أي زيادة في الكمية تمر حصريًا عبر زر **"+ تزويد المخزون"**، الذي يطلب دومًا كمّية جديدة وسعر شراء، ويحسب متوسط سعر شراء مرجّحًا يحافظ على قيمة الكمية القديمة بدل محوها.

### الطلبات
كل طلب يقوم به زبون من المتجر يظهر مباشرة في تبويب **"الطلبات"** مع الولاية، البلدية، العنوان الكامل، طريقة التوصيل، ورقم الهاتف. الطلبات مقسّمة إلى فلاتر:
- **الطلبات الحالية**: كل الطلبات التي لم تُسلَّم بعد ولم تُلغَ (قيد المعالجة / قيد التوصيل).
- **الأرشيف (المسلَّمة)**: الطلبات التي وصلت فعليًا للزبون، مؤرشفة هنا بشكل منفصل.
- **الملغاة**: الطلبات التي أُلغيت.
- **الكل**: عرض شامل.

يمكنك حذف أي طلب نهائيًا بزر "حذف". قواعد الحذف دقيقة ومنطقية:
- **طلب "تم التسليم"**: لا يُعاد مخزونه أبدًا (المنتج بيع فعليًا وخرج للزبون)، ومبيعاته وتكلفة شحنه تبقيان محتسبتين في الأرباح للأبد عبر أرشيف مالي دائم، حتى بعد حذف سجل الطلب نفسه.
- **طلب "ملغي"**: لا يُعاد مخزونه عند الحذف لأنه أُعيد مسبقًا وقت الإلغاء.
- **طلب "قيد التوصيل"**: المخزون يعود دائمًا (البضاعة لم تصل للزبون بعد مهما كانت النتيجة)، لكن النظام يسألك صراحة **"هل خسرت ثمن التوصيل فعليًا؟"** قبل الحذف — إن أجبت بنعم (ذهب المندوب ودُفعت التكلفة) تُحتسب خسارة الشحن، وإن أجبت بلا فلا خسارة إطلاقًا.
- **طلب "قيد المعالجة"**: يُعاد مخزونه بالكامل عند الحذف لأن البيع لم يكتمل فعليًا بعد.

### الأرباح والخسائر (30 يومًا) — بسعر الشراء الحقيقي
تبويب **"الأرباح (30 يوم)"** منفصل تمامًا عن ملخص "الطلبات"، ويحسب الربح الحقيقي: (سعر البيع − سعر الشراء المسجَّل فعليًا وقت تلك العملية بالذات، وليس سعر اليوم) لكل قطعة بيعت ووصلت فعليًا للزبون خلال آخر 30 يومًا، مطروحًا منه تكلفة الشحن المدفوعة فعليًا خلال نفس الفترة. يعرض أيضًا أعلى 10 منتجات ربحًا.

### حساب الأرباح (المخصوم منه تكلفة الشحن)
أعلى تبويب "الطلبات" تجد 3 بطاقات محدَّثة تلقائيًا:
- **مبيعات الطلبات المسلَّمة**: مجموع أسعار المنتجات (بدون التوصيل) للطلبات التي وصلت فعليًا للزبون فقط (نظام الدفع عند الاستلام الشائع في الجزائر).
- **تكلفة الشحن المخصومة**: بمجرد أن يتحول الطلب إلى **"قيد التوصيل"** لأول مرة (أي بمجرد تسليمه لشركة التوصيل)، يُخصم سعر توصيله فورًا من الحسابات — حتى قبل وصوله فعليًا للزبون — لأن تكلفة الناقل تُدفع بمجرد الشحن بغض النظر عن نجاح التسليم. **هذه الخسارة تبقى محتسبة حتى لو أُلغي الطلب لاحقًا** (مثلًا لو رفض الزبون الاستلام)، لأن المال دُفع فعليًا لشركة التوصيل ولا يُسترجع بمجرد الإلغاء. إن أردت إسقاط هذه الخسارة من الحسابات نهائيًا، الحل الوحيد هو حذف الطلب نهائيًا بزر "حذف".
- **صافي الربح** = مبيعات الطلبات المسلَّمة − تكلفة الشحن المخصومة.

### أسعار التوصيل حسب الولاية
من تبويب **"أسعار التوصيل"** تجد جدولًا بكل ولايات الوطن الـ69، ولكل ولاية حقلان:
- **سعر التوصيل للمنزل**
- **سعر التوصيل لمكتب البريد (Stop Desk)**

اكتب الأسعار التي تريدها (بالدينار الجزائري) ثم اضغط **"حفظ كل الأسعار"**. اترك الحقل `0` لأي ولاية لا توصّل إليها حاليًا (ستظهر بسعر 0 عند الزبون، لذا يُفضّل تعبئتها كلها قبل النشر الفعلي). عند إتمام الزبون لطلبه، يختار ولايته وبلديته من قائمتين منسدلتين (تُحمَّل تلقائيًا من قاعدة بيانات الولايات/البلديات)، ثم يختار طريقة التوصيل، فيُحسب السعر النهائي فورًا. **مهم أمنيًا**: السعر المعروض للزبون هو للعرض فقط؛ عند إرسال الطلب فعليًا يعيد السيرفر حساب سعر التوصيل من الجدول الذي أدخلته أنت، فلا يستطيع أي زبون التلاعب بالسعر عبر أدوات المتصفح.

## 3) روابط التواصل الاجتماعي (أيقونات في الموقع)
من تبويب **"الربط مع السوشيال ميديا"** اكتب روابط واتساب/انستغرام/فيسبوك/تيك توك/تلغرام الخاصة بمتجرك. أي حقل تتركه فارغًا لا تظهر أيقونته إطلاقًا في الموقع (لا حاجة لحذف أزرار يدويًا). بمجرد الحفظ، تظهر الأيقونات تلقائيًا في 3 أماكن:
- شريط رفيع أعلى الصفحة الرئيسية.
- أسفل الصفحة الرئيسية (الفوتر).
- بجانب زر "أضف للسلة" في صفحة كل منتج.

لواتساب، يمكنك كتابة رقم دولي خام بدون علامة + (مثال: `213555000000`) أو رابط `wa.me` كامل، وكلاهما يعمل.

## 4) حاسبة التسعير والإعلانات
تبويب **"حاسبة التسعير والإعلانات"** أداة حية (حساب فوري بدون زر "احسب") لمعرفة ربحك الحقيقي قبل إطلاق أي حملة إعلانية:
- اختر منتجًا موجودًا فتُملأ أسعاره تلقائيًا، أو أدخل الأرقام يدويًا لمنتج تفكّر فيه.
- أدخل تكلفة الشحن، التغليف، وتكلفة إضافية لكل طلب (مثل الاتصال للتأكيد أو نسبة الإرجاع المتوقعة).
- تعرض الحاسبة: هامش الربح الحقيقي للقطعة، **أقصى مبلغ يمكنك دفعه كإعلان لكل عملية بيع دون خسارة**، وعدد القطع التي يجب بيعها شهريًا لتغطية مصاريفك الثابتة (يمكنك إضافة أي عدد من بنود المصاريف الثابتة بأسماء حرة).
- بانر ملوَّن يخبرك فورًا: أخضر (رابح)، أصفر (تكلفة الإعلان الحالية تتجاوز هامشك، مع الرقم الدقيق الذي يجب تخفيضه إليه)، أو أحمر (سعر البيع لا يغطي حتى التكلفة الأساسية).

## 5) الربط مع فيسبوك، انستغرام، وتيك توك — كيف يعمل فعليًا؟

**مهم جدًا أن تفهم هذه النقطة:** لا يوجد أي كود أو موقع يستطيع "النشر التلقائي المباشر" داخل حسابك في فيسبوك/انستغرام/تيك توك بدون موافقتك وربط حساب تجاري (Business Account) تملكه أنت. هذا ليس قيدًا في هذا المشروع، بل هو نظام أمان تفرضه هذه المنصات نفسها لحماية حسابات مستخدميها من أي موقع خارجي.

**الطريقة الصحيحة والمعتمدة رسميًا** هي عبر **"ملف كتالوج المنتجات" (Product Feed)**: ملف يُنشئه موقعك تلقائيًا ويحتوي كل منتجاتك (الاسم، السعر، الصورة، الرابط)، وتقوم أنت بإعطاء رابط هذا الملف لفيسبوك/تيك توك، فتقوم هي بقراءته وتحديثه تلقائيًا كل يوم.

هذا الموقع **يولّد لك هذه الملفات جاهزة تلقائيًا** من قاعدة بياناتك:

| المنصة | الرابط | طريقة الربط |
|---|---|---|
| فيسبوك / انستغرام | `https://رابط-موقعك/api/feed/facebook.xml` | افتح [Meta Commerce Manager](https://business.facebook.com/commerce) ← Catalog ← Add items ← Data Feed ← الصق الرابط واضبط جدولة يومية |
| تيك توك شوب | `https://رابط-موقعك/api/feed/tiktok.csv` | من TikTok Seller Center ← Products ← Bulk/Scheduled Feed ← الصق الرابط |

هذه الروابط تظهر أيضًا جاهزة لك داخل لوحة التحكم، تبويب **"الربط مع السوشيال ميديا"**.

**شروط عمل الربط:**
1. يجب نشر موقعك على نطاق (Domain) حقيقي يدعم HTTPS (localhost لا يعمل مع فيسبوك/تيك توك).
2. يجب أن يكون لديك حساب Business Manager على فيسبوك وحساب Seller على تيك توك (مجانيان، تنشئهما بنفسك).
3. اضبط `STORE_URL` في ملف `.env` على رابط موقعك الحقيقي بعد النشر حتى تكون روابط الصور صحيحة.

بعد الربط، أي منتج تضيفه أو تعدّله من لوحة التحكم سيظهر تلقائيًا (خلال ساعات حسب جدولة كل منصة) في متجرك على فيسبوك وانستغرام وتيك توك، بدون أي عمل يدوي إضافي.

## 6) النشر على الإنترنت (Hosting)

هذا مشروع Node.js عادي، يمكنك نشره على أي من:
- **Railway** أو **Render**: يدعمان Node.js + قواعد بيانات SQLite مباشرة (الأسهل للمبتدئين).
- **VPS خاص** (مثل Hetzner، DigitalOcean) مع Nginx كـ reverse proxy و PM2 لتشغيل السيرفر باستمرار، ثم شهادة SSL مجانية عبر Let's Encrypt.

بعد النشر لا تنسَ:
- تحديث `ALLOWED_ORIGINS` في `.env` برابط نطاقك الحقيقي (وليس localhost).
- تحديث `STORE_URL` بنفس الرابط.
- التأكد أن `NODE_ENV=production` مضبوط حتى تُفعَّل الكوكيز الآمنة (Secure Cookies).

## 7) ملخص الإجراءات الأمنية المطبّقة

- **كلمات المرور**: مشفّرة بـ bcrypt (لا تُخزَّن أبدًا كنص واضح).
- **الجلسات**: JWT داخل كوكي HttpOnly (لا يمكن لجافاسكربت في المتصفح قراءته، يقلل خطر XSS).
- **Rate Limiting**: حماية من محاولات تخمين كلمة المرور (8 محاولات/15 دقيقة) وحماية عامة على كل الـ API.
- **Helmet**: يضبط ترويسات HTTP الأمنية (CSP, XSS Protection...).
- **التحقق من المدخلات**: كل بيانات القادمة من المستخدم (تسجيل الدخول، الطلبات، المنتجات) تُتحقق منها بصرامة بـ express-validator قبل معالجتها.
- **رفع الملفات**: مقيّد بنوع الصور فقط (JPEG/PNG/WEBP/GIF)، بحجم أقصى 5MB، وأسماء ملفات عشوائية آمنة (لا تُستخدم أسماء الملفات الأصلية القادمة من المستخدم).
- **الأسعار**: يُعاد حسابها من قاعدة البيانات عند إتمام الطلب (لا يُوثق بالسعر القادم من المتصفح لمنع التلاعب).
- **CORS**: مقيّد فقط بالنطاقات المسموحة التي تحددها أنت.

**تذكير مهم:** غيّر `JWT_SECRET` وكلمة مرور الأدمن في `.env` قبل أي نشر فعلي، ولا تشارك ملف `.env` مع أي أحد أو ترفعه على GitHub علنًا.

## 8) هيكل المشروع

```
ecommerce-store/
├── server.js              # نقطة انطلاق السيرفر وكل إعدادات الأمان
├── db.js                  # تعريف قاعدة البيانات والجداول
├── scripts/createAdmin.js # إنشاء أول حساب أدمن
├── middleware/auth.js     # التحقق من تسجيل الدخول
├── routes/
│   ├── auth.js            # تسجيل الدخول/الخروج
│   ├── categories.js      # التصنيفات (بما فيها زر +)
│   ├── products.js        # المنتجات
│   ├── orders.js          # الطلبات
│   ├── feed.js             # كتالوج فيسبوك/تيك توك
│   └── upload.js          # رفع الصور
└── public/
    ├── index.html          # واجهة المتجر
    ├── admin.html          # لوحة التحكم
    ├── product.html        # صفحة تفاصيل منتج
    ├── css/style.css
    └── js/{store,admin,cart}.js
```
